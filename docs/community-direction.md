# 社区贡献方向

2026-09-17 确认，2026-09-18 归档整合。这是下一阶段的产品与贡献目标，不是已完成能力或社区采纳声明。

## 产品目标

**自主接入与可靠接续**：用户能够接入自己的另一个独立 runtime，把当前会话交给它继续执行，再接回来；清楚知道执行位置、信息交付范围和失败后的恢复位置。

设计继续坚持小核心、明确边界、可选插件和工作台可组装。逻辑会话、Home、当前执行端、模型位置与授权范围分别表达。

## 社区贡献目标

> “自主接入与可靠接续”可以继续作为下一阶段产品目标，但实现方案应先对照 `dsh-distribution` 的环境身份和 `dsh-std` 的连接边界。我们最值得建立的社区位置，是：ARC 持续提供真实的跨 runtime 接力案例，把公共接口的缺口测出来、补清楚，并让其他工作台能够复用。

- 参考 [dsh-distribution](https://github.com/T-Auto/dsh-distribution) 的环境与安装实例身份，参考 [dsh-std](https://github.com/Yan-Zero/dsh-std) 的连接、会话和调用边界；两者当前仍为草案，不假定所有设计已有实现。
- 优先贡献可复现的接力场景、失败行为和互操作测试；历史导入的来源验证、重复请求与部分完成结果是候选讨论方向。
- 普通工具、模型 provider、界面与工作流按自身职责演进；ARC 不要求成为所有调用的中心服务器。
- Home、受限委派和信息状态同步按证据逐步演进，不提前固定最终算法或宣称安全隔离。
- 保持 ARC 独立可用，通过可选适配让其他工作台复用；未来可争取范例收录和共同维护，结果以相关维护者的明确决定为准。

推进建议与验收出口见 [下一阶段技术路线](next-stage.md)，社区规则与接口状态见 [调查记录](research/dsh-community-contribution-2026-09-17.md)。
